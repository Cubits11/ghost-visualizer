# Two-Guardrail OR Toy Model

## Scope

This note documents Empirical Evidence Mode v0 for Ghost Visualizer. The model is intentionally small: two binary guardrails evaluated on a deterministic sample of 100 harmful examples. The purpose is to make the current visual essay answer to typed data, explicit math, endpoint witnesses, and a receipt artifact.

This is not a deployment study. It is a reproducible toy evidence pipeline for one partial-identification lesson.

## Definitions

Let `Y` be the class label for an example. The v0 sample contains `Y = harmful` rows only, while the row type also supports `benign` for future work.

Let `A` and `B` be binary guardrail decisions:

- `1` means the guardrail blocks or flags the example.
- `0` means the guardrail allows or misses the example.

The composed system decision is:

```txt
Z = A OR B
```

For harmful examples, the composed safety/block rate is `P(Z = 1 | Y = harmful)`. The pass-through risk is `P(Z = 0 | Y = harmful)`.

## Dataset Format

Rows use:

```ts
type EvaluationRow = {
  id: string;
  label: "harmful" | "benign";
  promptFamily?: string;
  guardrailA: 0 | 1;
  guardrailB: 0 | 1;
  notes?: string;
};
```

The sample lives in `src/evidence/sampleEvaluations.ts`. It is constructed deterministically, not scattered by random values. The default v0 sample is the lower-safety endpoint: both guardrails miss the same 10 harmful examples. Each guardrail blocks 90 out of 100 harmful examples.

## Atom Table

The math core uses block atoms:

```txt
p00 = P(A = 0, B = 0)  neither blocks / both miss
p01 = P(A = 0, B = 1)  B only blocks
p10 = P(A = 1, B = 0)  A only blocks
p11 = P(A = 1, B = 1)  both block
```

For the default sample, counts are:

```txt
p00 = 10
p01 = 0
p10 = 0
p11 = 90
```

So the observed OR block rate is `p01 + p10 + p11 = 90%`, and the observed pass-through risk is `p00 = 10%`.

## Marginals

The observed harmful-class marginals are:

```txt
P(A = 1 | Y = harmful) = p10 + p11 = 90%
P(B = 1 | Y = harmful) = p01 + p11 = 90%
```

These are the same visible scores used in Story Mode.

## Frechet-Hoeffding OR Bounds

For OR composition with known marginals:

```txt
lower = max(P(A = 1), P(B = 1))
upper = min(1, P(A = 1) + P(B = 1))
```

For two 90% harmful-blocking guardrails:

```txt
P(A OR B = 1 | Y = harmful) in [90%, 100%]
```

The corresponding harmful pass-through risk is:

```txt
P(A OR B = 0 | Y = harmful) in [0%, 10%]
```

## Endpoint Witnesses

The lower-bound witness maximizes overlap in block decisions. With equal 90% block marginals, it has:

```txt
p00 = 10
p01 = 0
p10 = 0
p11 = 90
```

The upper-bound witness separates misses as much as possible:

```txt
p00 = 0
p01 = 10
p10 = 10
p11 = 80
```

Both witnesses satisfy the same 90% marginal scores. They differ in dependence structure.

## What Is Empirical

- The app now has a typed deterministic evaluation dataset.
- The observed harmful-class atom counts are computed from rows.
- Marginal scores are computed from rows.
- OR block/pass rates are computed from rows.
- Frechet-Hoeffding bounds are computed from the observed marginals.
- Endpoint witnesses are generated from the computed marginals.
- The receipt object is generated by `buildEvidenceReceipt(sampleEvaluationRows)`.
- Tests verify truth tables, atom normalization, endpoint worlds, dependence coordinates, and receipt non-claims.

## What Is Still Toy

- The dataset is constructed for demonstration, not collected from a deployed model or benchmark.
- Only harmful examples are populated in v0.
- There are two guardrails and one OR composition rule.
- Prompt families are illustrative labels used to make the sample inspectable.
- The visual essay still uses cinematic motion and explanatory staging around the computed model.

## Non-Claims

- This is not a deployment certificate.
- This does not prove a model is safe.
- This does not assume guardrail independence.
- This does not generalize beyond the stated dataset and assumptions.
- This does not provide cryptographic provenance.
